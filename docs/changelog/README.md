# Changelog

## Purpose

Where release and changelog content lives, so nothing is duplicated here. This folder deliberately holds no entries.

## Where the content is

| What | Where | Audience |
| --- | --- | --- |
| Public product changelog | Markdown files read from `content/changelog/*.md` by `src/lib/changelog.ts`, rendered at `/changelog` (`app/(web)/changelog/`) | Customers, pt-BR |
| Per-deploy release notes | GitHub Releases, generated by `gh release create --generate-notes` in `cd.yml` | Developers |
| History of what changed and why | Conventional Commits on `main` (`git log`) | Developers |
| Architecture decisions | [../adr/README.md](../adr/README.md) | Developers |
| Incidents | [../postmortems/README.md](../postmortems/README.md) | Developers |
| Release writeups, operation logs | The Obsidian vault outside this repository (`Changelog/`, `Claude/history/`), per `CLAUDE.md` | Owner |

## How the public changelog works

- `src/lib/changelog.ts` lists `content/changelog/*.md`, parses the frontmatter with `ChangelogEntryFrontmatterSchema` (`src/schemas/changelog-entry.schema.ts`: `title`, `slug`, `date`, `summary`, `improvements[]`, `fixes[]`), compiles the Markdown body with a sanitizing pipeline (`rehype-sanitize`) and sorts entries by date, newest first.
- The body is the "Novidades" part; `improvements` and `fixes` are one-liners kept in the frontmatter so they render as collapsible lists. The slug `page` is reserved for pagination (5 entries per page, `CHANGELOG_PAGE_SIZE`).
- Reads are cached with `'use cache'` and `cacheLife('max')`, so a new file needs a new build and deploy to appear.
- Entries are written in pt-BR (product copy). `/changelog` is a public route in `proxy.ts`.
- The folder `content/changelog/` does not exist in the repository today; `listEntryFiles` treats a missing folder as empty (`ENOENT`), so the page renders with no entries. The feature arrived in `68eed4ff` (2026-10-29). Whether entries are meant to be committed to this repository or kept elsewhere: TODO: confirm.
- Blog posts live beside it in `content/blog/`.

## Adding an entry

Add `content/changelog/<slug>.md` with the frontmatter above, commit to `main`, and let CD deploy. Markdown under the app tree is rendered content, which is why `ci.yml` ignores only root-level `*.md`.
